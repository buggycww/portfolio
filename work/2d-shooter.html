2D-Shooter

A 2D action platformer built without an engine — because I wanted to understand the parts an engine normally hides.

I built 2D-Shooter to learn what an engine does for you. No Unity, no Unreal: SDL3 for windowing, input, and audio; tinyxml2 for TMX maps; C++17 for everything else.

Custom engine AABB collision Quadtree TMX tilemaps Profiling

The frame

The game runs on a delta-time loop: poll events, update every dynamic object, resolve collisions, draw the scene, present. The same loop also collects frame, update, and draw timings so I can see where the time goes without attaching a profiler.

The viewport follows the player with a vertical dead-band and an exponential smoothing factor, so the camera does not snap when the player crosses a threshold. The background is drawn in four parallax layers at different scroll factors.

Collision, in two passes

Collision is AABB, resolved one axis at a time. On each axis the game tests actors first, then re-queries the static level at the tentative position. Static geometry is resolved last so it always wins — a player pushed by an enemy cannot end up inside a wall. 

// actors first, then re-query the level at the new position
for (const ObjectRef& ref : gs.actors) resolveAgainst(...);
gs.collision.query(colliderBounds(obj, tentativePos), levelCandidates);
for (GameObject* objB : levelCandidates) resolveAgainst(*objB);

A one-pixel sensor under the player handles grounding. Bullets use the movement-axis rule instead of shallowest-axis resolution: they are small and fast enough that the shallowest axis can pop them out of the top or bottom of a wall instead of stopping them.

A quadtree, not a point tree

My first quadtree only indexed points, which is not enough to find boxes that overlap a collider — a large box can overlap a query while its centre sits outside it. The broad phase stores a full AABB for every entry.

A box is stored exactly once, in the deepest node that fully contains it. Boxes that straddle a split stay in the parent, and a query tests every visited node, so those boxes are still found. Half-open intervals ([x, x+w)) guarantee that a point on a boundary belongs to exactly one child. 

// half-open intervals keep points in exactly one child
bool AABB::contains(float px, float py) const {
  return px >= x && px < x + w &&
         py >= y && py < y + h;
}
An engine is a set of decisions. Building without one made those decisions visible.

Content and state

Levels load from TMX, with tile layers and object groups. Tiles are mapped through their first GID into the right tileset, then turned into static level objects. Players and enemies are spawned from the object layer, which keeps level authoring out of the code.

Animation is a small state machine: idle, running, jumping, hit, dead. Some states preserve the run-cycle phase when transitioning so the legs do not reset mid-stride. Audio is handled through SDL3_mixer for music, shooting, hits, and jump sounds.

Instrumentation

The debug overlay shows FPS, frame time, worst frame, update time, draw time, player state, grounded state, active bullets, enemies, objects, quadtree node count, and quadtree entry count. It turns “it feels slow” into a number I can compare across changes.

What I’d change

Move physics to a fixed timestep so collision behaviour is reproducible across frame rates. Add automated tests around the quadtree and AABB edge cases. Revisit the dynamic object path once actor counts grow beyond the current small set.

What it taught me

Broad phase and narrow phase are separate problems. Half-open intervals remove a whole class of duplicate-query bugs. And an overlay that shows the frame is worth more than a guess about where the time went.
