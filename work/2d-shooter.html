2D-Shooter

A 2D action platformer built from scratch in C++17 and SDL3. No engine.

Role

I built 2D-Shooter to learn what a game engine does. It uses SDL3 for windowing, input, and audio, tinyxml2 for TMX maps, and C++17 for the rest.

What I did

  • Wrote the game loop, input, rendering, audio, and asset loading.
  • Added box (AABB) collision with per-axis resolution. Actors resolve first, then level geometry.
  • Used a quadtree for collision checks so the game does not test every object against every tile.
  • Loaded levels from TMX files and spawned players and enemies from the map data.
  • Added animation states, parallax backgrounds, and a debug overlay with frame and quadtree stats.

Collision

Movement resolves one axis at a time. The game tests actors first, then rechecks the level at the new position. Static geometry is resolved last, so the player cannot be pushed into a wall. Bullets use the movement axis instead of the shallowest axis, because small fast objects can pop out of walls.

Why this quadtree uses boxes

My separate quadtree visualiser stores points. For collision, a point is not enough: a large box can overlap the player while its centre is outside the player. 2D-Shooter stores an axis-aligned box for each object instead, so collision checks can find every box that overlaps a query. The idea is the same; the stored shape is different.
